DSAL Theory & Viva Preparation

Learn the Algorithm

Comprehensive conceptual breakdown, complexities, and expected viva questions designed for your end-term laboratory examination.

1. What is a Stack? (LIFO)

A Stack is a linear data structure following the Last-In, First-Out (LIFO) principle. The most recently inserted element (via push()) is always the first one to be removed (via pop()). Access is strictly restricted to a single endpoint called the top.

  • push(Cell): Inserts a newly discovered cell onto top of stack.
  • pop(): Deletes the top cell when retreating from a dead end.
  • top(): Inspects current coordinates without removing.
  • empty(): Checks if stack has remaining coordinates to explore.

2. What is Backtracking?

Backtracking is an algorithmic paradigm that systematically searches for solutions by exploring all potential paths. When the search hits a dead end (a state where no valid move can lead to the destination), the algorithm abandons the branch and backtracks to the previous decision point.

  • Systematic trial-and-error approach.
  • Never visits an invalid or blocked cell twice.
  • Restores state dynamically using the stack history.

3. Why is Stack Suitable for this?

A stack natively records the exact trail of our journey. The top element is always our current position. When we hit a dead end, calling s.pop() automatically returns us to the exact cell we came from, allowing our else if cascade to evaluate the remaining candidate directions seamlessly.

4. The Visited Array (`bool** visited`)

Without tracking visited cells, the solver would jump endlessly back and forth between adjacent open cells (e.g., from (0,0) to (1,0) and back to (0,0)), causing an infinite loop. Marking cells as visited = true upon push guarantees every cell is evaluated at most once.

5. Direction Priority Hierarchy

My algorithm evaluates neighbors in a strict four-step deterministic priority order:

  1. Down: (r + 1, c)
  2. Right: (r, c + 1)
  3. Up: (r - 1, c)
  4. Left: (r, c - 1)

The first valid unvisited neighbor is selected. If all 4 fail, moved remains false, triggering s.pop().

6. What Happens at a Dead End?

When the cell at s.top() has no valid unvisited neighbor in any of the 4 directions, the flag bool moved remains false. The condition if (!moved) s.pop(); executes. The dead-end cell is discarded from the stack, and the while loop inspects the previous top.

Time Complexity $\mathcal{O}(R \times C)$

In a grid of $R$ rows and $C$ columns, there are at most $R \times C$ total cells. Because every cell is marked in the visited array upon being pushed, no cell is ever pushed or popped more than once. Evaluating the four neighbors takes $\mathcal{O}(1)$ constant time per cell. Hence, total runtime is strictly bounded by $\mathcal{O}(R \times C)$.

Auxiliary Space Complexity $\mathcal{O}(R \times C)$

The auxiliary space consists of two main structures: (1) The dynamically allocated 2D visited boolean table requiring $R \times C$ memory; (2) The STL stack<Cell>, which in the worst-case (a snake-like maze) holds up to $R \times C$ cells. Thus, total auxiliary space is $\mathcal{O}(R \times C)$.

1. struct Cell

Encapsulates row and column index into a lightweight value type. Stored directly within std::stack<Cell> without pointer overhead.

2. isValid()

Ensures coordinate within $[0, rows-1]$ and $[0, cols-1]$, validates maze[r][c] == 1 (open path), and checks !visited[r][c].

3. s.push() & visited[r][c] = true

Cell is marked visited immediately when pushed. This critical design choice prevents cyclic re-exploration.

4. Path Reversal via Secondary Stack

Because the primary stack holds the path from destination down to start (LIFO), popping into a secondary stack and printing reverses it to proper start-to-destination order.

5. Dynamic Memory Management

All dynamically allocated 2D arrays (new int*[rows] and new bool*[rows]) are cleanly deleted via delete[] loops to eliminate memory leaks.
